# BE-27 Phase 1 — thông báo trong ứng dụng (05/10/2026, claude)

## Hướng chung

Bảng `notification`, mỗi dòng là **một thông báo cho một người**. Dòng được **stage trong cùng DbContext và
cùng `SaveChanges`** với thay đổi nghiệp vụ (khuôn `IAuditTrail`): việc rollback thì thông báo cũng không có.
Client **polling** (gợi ý: đếm chưa đọc mỗi 30–60 s khi app mở, tải danh sách khi người dùng mở chuông).
Push (Firebase) sau này là **thêm một kênh gửi** đọc từ cùng bảng — API polling giữ nguyên.

## API đề xuất (mọi vai trò, chỉ thấy thông báo của chính mình)

```
GET  /api/v1/notifications?unread_only=&page=&page_size=   → {page, page_size, total, unread_count, items[]}
GET  /api/v1/notifications/unread-count                    → {unread_count}
POST /api/v1/notifications/{notification_id}/read          → 204 (idempotent)
POST /api/v1/notifications/read-all                        → 204
```

```json
{ "notification_id": "NTF-000123", "type": "work_order_assigned",
  "title": "Bạn được giao phiếu sửa chữa", "body": "WO-0042 — Thay bóng tuyến Long Phước 2, hạn 12/10/2026",
  "entity_type": "work_order", "entity_id": "WO-0042",
  "created_at": "2026-10-05T08:00:00Z", "read_at": null }
```

Sắp `created_at DESC, length(id) DESC, id DESC` (khuôn ID mục 0). Thông báo của người khác → 404.

## Sự cố → ai nhận (phạm vi đề xuất = D-1 phương án b)

| `type` | Khi nào | Người nhận |
|---|---|---|
| `work_order_assigned` | Tạo phiếu có người được giao, giao, giao lại, phiếu tiếp nối có người | Kỹ sư **mới** được giao |
| `work_order_unassigned` | Bỏ giao / giao lại cho người khác | Kỹ sư **cũ** |
| `work_order_returned` | Quản lý trả phiếu (làm lại) | Kỹ sư được giao |
| `work_order_cancelled` | Huỷ phiếu đang có người | Kỹ sư được giao |
| `work_order_completed` | Kỹ sư báo xong (`done`, chờ nghiệm thu) | Quản lý của xã |
| `survey_returned` | Duyệt khảo sát: trả về | Kỹ sư đã quay (`captured_by`) |
| `survey_ready_for_review` | Xử lý sweep xong → `awaiting_review` | Quản lý của xã |
| `fault_reported` | Kỹ sư báo sự cố tại chỗ (BE-41) | Quản lý của xã |

- **"Quản lý của xã"** = tài khoản `manager`, đang hoạt động, có xã đó trong `app_user_commune`.
- **Không báo cho chính người gây ra** sự kiện.
- Ngoài phạm vi (cần BE-26 Hangfire): `work_order_overdue`, `node_offline`, sự cố CV mới — thêm `type` sau,
  không đổi API.

## Lược đồ đề xuất

```
notification
  notification_id  text PK DEFAULT luxmap_format_id('NTF', nextval('notification_id_seq'), 6)
  recipient_user_id text NOT NULL  FK app_user  RESTRICT
  commune_id       text NOT NULL   FK administrative_unit RESTRICT (HasCommuneReference)
  type             text NOT NULL   CHECK in (8 giá trị)
  title            text NOT NULL   (≤ 200)
  body             text NOT NULL   (≤ 1000)
  entity_type      text NOT NULL   CHECK in (work_order, survey_sweep, fault)
  entity_id        text NOT NULL
  created_at       timestamptz NOT NULL
  read_at          timestamptz NULL
INDEX (recipient_user_id, created_at DESC)  ;  partial (recipient_user_id) WHERE read_at IS NULL
      + HasIndex(commune_id) tường minh (quy ước partial index)
```

`entity_id` **không FK** (ba bảng khác nhau) — thông báo là bản chụp, không phải tham chiếu sống; client mở
entity qua endpoint thường, quyền xem do endpoint đó quyết (có thể 404 nếu đã bị giao cho người khác).
